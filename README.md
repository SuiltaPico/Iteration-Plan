# 迭代策略 (Iteration Plan)

用「试用 → 打分 → 留存 / 淘汰」的方式管理你的各种策略。

- **主题 → 问题 → 候选策略**：主题是一个领域（投资、学习…），问题是里面要解决的一件具体的事（「什么时候卖出」），问题下放几种候选策略，各自试用、复盘，留下最适合你的。某个候选留存后，会提示其他候选要不要退场。
- **策略**：所见即所得的 Markdown 编辑器（标题、列表、任务清单、表格、代码块、LaTeX 公式、图片，`/` 唤出菜单）。每个策略写一条「怎么判断有效」，复盘时对照它回答。
- **保存、版本与草稿**：
  - 正式策略的修改要点「保存」（Ctrl/⌘+S）。小改动直接保存，分数保留；大改动选「存为新版本」，分数清零重新试用，旧复盘标着旧版本号；也可以「另存为新策略」，会记下是从哪条改来的。
  - 没保存就离开（包括关掉页面），修改会克隆成草稿，原策略不变。草稿可以「开始试用」或「覆盖原策略」。新建的策略先是草稿。
- **复盘**：卡片或策略页上点「复盘」，进入只有这一个策略的专注页。结果分三种：执行了·有效（+1）、执行了·无效（−1）、没怎么执行（不计分）；还可以只记录观察。连续「没怎么执行」会提示你把策略简化。
- **问一问**：总览页每天最多主动问一个策略「你觉得它怎么样」，可以「说说看」或「过几天再问」。多久问一次按主题设置（默认试用中 7 天、已留存 30 天），复盘过就重新计时。
- **记一笔**：右下角「＋ 记一笔」或策略页上的按钮，随手记下某次实际用了策略的情况和结果（不计分）。复盘时会列出上次复盘以来记的每一笔。
- **关于我**：跨主题的个人规律（什么做法适合你、什么坚持不了）。自己写，或让 AI 从踩过的坑、没怎么执行的复盘和使用记录里提炼；AI 出任何主意前都会先读。
- **踩过的坑**：策略被淘汰时记下为什么不行，汇总在主题的「踩过的坑」里，AI 出主意时也会参考。
- **打法**：主题的「打法」视图把已留存的策略按问题汇总成一页，决策时直接翻。
- **AI 助手**（右下角 ✦ AI，或各页面上的 ✦ 按钮）：建主题、问题和候选策略，帮写/润色，根据复盘和踩过的坑给建议，也可以对话式地打分、淘汰、移动。AI 的改动直接写入数据。

数据保存在浏览器本地（IndexedDB）。侧边栏底部可以：

- **同步到 GitHub**：填一个仓库和 token，数据会自动提交到仓库里——`data.json` 是完整数据，另有每个策略一篇的 Markdown、各主题的「打法」和「踩过的坑」、「关于我」，方便直接阅读和搜索。多台设备填同一个仓库就能同步，同一条记录以较新的修改为准，删除也会同步。打开页面、修改后几秒、回到页面、每 5 分钟都会同步。
- **备份与恢复**：下载 / 复制 JSON 备份，或从文件 / 粘贴内容导入。

可以「添加到主屏幕」作为应用使用，离线也能打开；主屏幕图标长按有「记一笔」快捷入口。

## 开发

```bash
npm install
npm run dev      # 本地开发
npm run build    # 构建到 dist/，可直接部署到任意静态托管（如 GitHub Pages）
```

技术栈：Vite + React + TypeScript，Dexie (IndexedDB)，Milkdown Crepe 编辑器。

## 部署到 GitHub Pages

仓库自带 `.github/workflows/deploy.yml`：推送到 `main` 分支（或在 Actions 页面手动运行）时自动构建并发布。

首次使用需要在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。

另有 `npm run build:single`，把全部代码与字体打成一个 JS + 一个 CSS（输出到 `dist-single/`），适合只能放少量文件的托管环境。

## AI 设置

在 AI 面板里点 ⚙ 填写：

| 字段 | 说明 |
| --- | --- |
| 接口协议 | `OpenAI 兼容`（OpenAI、DeepSeek、通义、Kimi、OpenRouter 等）或 `Anthropic` |
| Base URL | 例如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、`https://api.anthropic.com/v1` |
| API Key | 只保存在当前浏览器的 localStorage |
| 模型 | 需支持工具调用，例如 `claude-opus-5-5`、`deepseek-chat` |

请求由浏览器直接发给你填写的地址（基于 [Vercel AI SDK](https://ai-sdk.dev)，纯前端，无需后端）。部分服务商或中转不允许浏览器跨域调用，此时会提示无法连接，换一个支持浏览器访问的地址即可。
